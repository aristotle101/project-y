# SNP-63820 — Hardline Hub Polygon Fallback

## สรุป

Feature/Bug ticket เกี่ยวกับ logic การเลือกช่องทางจัดส่ง (delivery/fulfillment) เมื่อที่อยู่ลูกค้าอยู่ใน polygon ของ Nextday และ/หรือ Hardline Hub โดยมี priority: **Nextday ก่อน Hardline** และมี fallback ไป Hardline Hub เมื่อไม่ตรง Nextday polygon

**Regression bug ที่เกี่ยวข้อง:** เคสที่อยู่ อ.สิชล จ.นครศรีธรรมราช (Lat 8.973887, Long 99.783398) — ไม่มี Nextday polygon ในพื้นที่ แต่ระบบดัน resolve ไปเจอ Hardline polygon ของสุราษฎร์ธานี ทำให้ Home/Cart แสดงสินค้า Nextday ของบิ๊กซีสุราษฎร์ธานีผิดพลาด (ต้องถูกบล็อกที่ Checkout)

## Coverage ของ test cases

- **Functional:** 7 เคส — ครอบคลุม polygon matrix ทั้ง 4 กรณี (มีทั้งสอง / มีแค่ Nextday / มีแค่ Hardline / ไม่มีเลย), priority fallback logic (Nextday > Hardline), regression เคสสิชล
- **Boundary:** 2 เคส — ขอบเขตระยะ 500 เมตรของการจับคู่ที่อยู่ที่บันทึกไว้
- **Validation/Negative:** 6 เคส — บล็อกการเลือก delivery type ที่ไม่ตรง coverage, ข้อความ error ภาษาไทยที่ถูกต้อง, บล็อก Nextday ที่ mismatch region

**รวม:** Functional 7, Boundary 2, Validation/Negative 6 (6/15 = 40%)

รายละเอียด test case ทั้งหมด: [`test-cases/SNP-63820.md`](../test-cases/SNP-63820.md)

## Key business rules ที่ต้องจำ

1. **Priority order:** ถ้าที่อยู่ตรงทั้ง Nextday และ Hardline polygon → เลือก Nextday ก่อน
2. **Fallback:** ถ้าไม่ตรง Nextday แต่ตรง Hardline → fallback ไป Hardline Hub ที่ใกล้ที่สุด
3. **ไม่มี coverage เลย** → เหลือแค่ Pickup/Parcel; Express/Nextday/Bulky ต้องเลือกไม่ได้
4. **ไม่พบ polygon ใดเลย** (resolve ไม่ได้สาขา) → ต้องแสดง error message: "พื้นที่นี้ไม่รองรับการจัดส่ง ลองเลือกที่อยู่ใหม่หรือรับที่สาขาแทน"
5. **ระยะจับคู่ที่อยู่บันทึกไว้:** เกณฑ์ 500 เมตร — พอดี 500m ยัง match ได้, เกิน 500m (เช่น 501m) ต้อง fallback ไป Default พระราม 4
6. **ไม่มีที่อยู่บันทึกไว้เลย** → Default เป็นพระราม 4 และบังคับ Delivery Type = Pickup เท่านั้น
7. **บั๊กเคสสิชล:** ช่องว่างระหว่าง "การแสดงผล" (Home/Cart แสดง Nextday ผิดพลาด) กับ "การบังคับใช้จริง" (Checkout ต้องบล็อก Nextday ที่ mismatch region)
